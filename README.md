# Бот ставок на площадке РАУ (СРО «Гарант»)

Что готово и проверено тестами:
- `rau_bot/calc.py`: расчёт минимальной ставки по правилам РАУ. Проверен на 4 реальных протоколах:
  среднее и победитель совпадают с протоколами; минимальные ставки: 75,22 / 35,00 / 14,92 / 26,19.
- `rau_bot/protocol.py`: чтение xlsx-протокола.
- `rau_bot/runner.py`: логика: ранняя заявка 0,01, за 10 минут до конца опрос каждые 15 с,
  подача только более высокой ставки, предел ставки, журнал `journal.csv`. Проверено с имитацией кабинета.

Что НЕ проверено (нужен сеанс на её компьютере): `rau_bot/browser.py`: поиск дела, чтение ставок со страницы,
заполнение формы и выбор сертификата. Написано по скриншотам и записи экрана.

## Установка (на её компьютере)
    pip install -r requirements.txt
    (playwright не скачивает браузер: подключаемся к её Яндекс.Браузеру)

## Запуск
1. Закрыть Яндекс.Браузер, запустить его с флагом `--remote-debugging-port=9222`, войти в кабинет через МЧД.
2. Скопировать `config.example.json` в `config.json`, `targets.example.csv` в `targets.csv`.
   targets.csv с заголовком: `inn;max_bid;initial;step;au1;au2;au_cap` (см. пример в файле).
   - предел ставки = минимум из max_bid, лимита АУ на дело (au_cap) и 805 (баллы СРО);
   - режим «физики»: max_bid=5, initial=0.1, step=0.5: ставки вида 0,1 / 0,6 / 1,1..., бот выбирает
     ближайшую сетке, которой достаточно, чтобы пройти единственной, и не выше предела;
   - баллы АУ площадка замораживает сама; бот читает «Доступные баллы» в форме, пишет их в журнал
     и не подаёт заявку, если ставка больше доступных.
3. Проверка расчёта:                  `python -m rau_bot check`
4. Ставка вручную из баллов конкурентов: `python -m rau_bot calc 3 3.1 7`
5. Сохранить страницу дела для отладки:  `python -m rau_bot dump <ИНН должника>`
6. Тренировочный режим (заполняет форму, НЕ подписывает): `python -m rau_bot run config.json targets.csv`
7. Боевой режим: в config.json поставить `"dry_run": false`.

## Допущения, которые нужно подтвердить
- Новая заявка выше прежней заменяет её (как сказала заказчица). Понижать ставку бот не пытается.
- Площадка сравнивает с округлённым или с точным средним: неизвестно, ставка считается безопасной при обоих.
- Время окончания считается по Москве.
- Не проверено: если повысить ставку новой заявкой, освобождаются ли баллы АУ по прежней, или замораживаются заново поверх. От этого зависит, сколько раз можно «перебивать». Смотреть по `journal.csv`: в нём пишутся доступные баллы АУ после каждой подачи.
- При нескольких делах подряд цикл опроса последовательный; при большом числе дел на 21.10 нужно параллелить вкладками.
